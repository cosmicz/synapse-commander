#+title: Synapse Commander — development
#+startup: overview

* Implementation boundary
The repository contains the Loop 0 backend smoke, not game behavior. The
selected engine path is Recoil/Beyond All Reason; the smoke runs the native
Linux headless engine. Demonstrate each runtime claim with a bounded run before
building on it.
Separate deterministic simulation, bounded unit controllers,
external reasoning and the human/spectator interface.

The simulation owns world state and validates all actions. Model requests
cannot grant unseen state, free computation, unlimited subagents or authority
over another faction. Proposed bot updates distinguish orders, whole program
replacement and physical upgrades; protocol details remain open.

* Verification contract
The first reproducible slice must show a unit performing useful work, a
consequential change in circumstances, and an observable response. Record
simulation and wall time, inputs, intent, acceptance, effects and human help.
Headless simulation and rendered interaction need separate checks.

Use bounded tests and fail-capable assertions. Preserve the same rules and
information boundaries across human, autonomous and mixed-team modes.
The bounded gateway smoke check below is the first application test coverage;
it does not imply runtime, gameplay, or rendered-client coverage.

* Bounded loopback gateway smoke check
The application now has a Python-standard-library boundary smoke check:
=python3 -m unittest discover -v=.  It starts an HTTP server bound only to
=127.0.0.1= in-process and exercises =GET /v1/observation= and
=POST /v1/intents=.  The gateway injects a fixed principal and team, emits a
bounded =synapse-smoke/v1= observation, and submits only typed =PRODUCE=,
=TASK=, or =INSTALL= =IntentEnvelope/v1= envelopes to a two-method replaceable
transport port. The listener rejects every non-loopback address.
It also requires an exact loopback Host header, rejects any Origin header, and
accepts POST bodies only as =application/json=. The only TASK is the
engine-smoke-only =advance= verb with empty arguments; it is not a Broken
Relay controller command. A =receipt_timeout= response is uncertain (HTTP 503),
not an engine rejection or physical outcome.
The in-memory transport is a deterministic test double, not an engine round
trip. Its reference validation enforces a simulation-frame token bucket of two
accepted intents per second with a burst of four and rejects duplicate IDs.
That limiter represents the authoritative synchronized dispatcher in test; the
HTTP gateway does not invent acceptance authority. The smoke payload's
=parameters= and =args= objects are intentionally empty, so later
controller-specific Broken Relay arguments cannot become an untyped escape
hatch here. A nonempty typed argument object, including the Loop 0
raw-engine-payload probe, is rejected at the gateway with =invalid_parameters=;
it is never forwarded to the engine.

This smoke schema is intentionally narrower than the selected Broken Relay
contract: it does not implement a Recoil bridge, radio delivery, controller
semantics, production legality, or effects.  An accepted intent receipt is
explicitly not an effect; physical effects remain the future authoritative
engine's separate records.  The port lives outside synchronized simulation and
does not accept raw Lua, console, or generic engine commands.

When a compatible recorder is supplied, the gateway emits =OBSERVATION=,
=INTENT_SUBMITTED=, and =INTENT_RECEIPT= ledger records with stable causal
links. The configured gateway origin is trusted configuration, never a caller
field. It records the whole normalized observation and typed envelope, not only
their identifiers. It emits no =EFFECT= record: that can only come from an
authoritative engine-side state change.

* Loop 0 native smoke
=python3 -m synapse_commander run-smoke= is the first end-to-end entry point.
It needs the pinned Recoil 2026.07.04 =spring-headless= (=--engine-dir=), an
engine data directory with =maps/supreme_isthmus_v2.1.sd7= (=--data-dir=), the
stock BAR checkout at =f6f07eaf= (=--game-dir=), a private evidence root
(=--out=), the project runtime lock directory (=--lock-dir=) and the rig commit
for the manifest (=--rig-commit=). All of these are supplied at launch; no host
path, credential or downloaded asset is stored in this repository.

=--engine-binary spring= runs the rendered client from the same engine
directory instead of =spring-headless=, with the same scenario, gateway, ledger
and verdict. The engine inherits the launcher's environment unchanged: =DISPLAY=
and GL settings are passed through, and the launcher sets none of them (no
=LD_PRELOAD= of its own). The private verdict records the inherited rendering
variables; the manifest carries only their hash and =presentation rendered=. A
rendered frame shows presentation; it does not change how the run's decisions
are classified. The exclusivity check counts both =spring-headless= and
=spring= processes.

On scenario-aware commands, =--scenario NAME= (for example =rescue_smoke=)
selects a =ScenarioTable/v1=
from =game/SynapseCommander.sdd/scenarios/= by adding =synapse_scenario=NAME=
to the start script's =[MODOPTIONS]=. The table is loaded and validated before
anything starts, and the
manifest records its id, version and hash. A table that declares an integer
=seed= sets the start script's =FixedRNGSeed= and the manifest's scenario seed
(otherwise both stay 1), and the verdict checks that the engine's hello echoes
the same seed. The scripted Loop 0 client and its verdict assume no scenario,
so =run-smoke --scenario NAME= is rejected before launch. Use =run-provision=
for the provisioning scenario check; it defaults to =rescue_smoke=.

| Layer | Module |
|-------+--------|
| Native launcher: run directory, start script, process group, lock | =synapse_commander/launch.py= |
| Orchestration, ledger ingestion, verdict | =synapse_commander/run.py=, =cli.py= |
| Scripted reference client (HTTP only) | =synapse_commander/agents/scripted.py= |
| Loopback gateway and intent schema | =gateway.py=, =protocol.py= |
| Engine port: file mailbox =synapse-mailbox/0= | =mailbox.py= |
| Engine side: synced validation/orders, unsynced mailbox I/O | =game/SynapseCommander.sdd= |
| Manifest, append-only ledger, verification | =recording.py= |

One run creates =OUT/RUN_ID/= and refuses to reuse it. Its =write/= directory is
the engine's =--write-dir=, with =games/BAR.sdd=, =games/SynapseCommander.sdd=
and the map linked in, a generated start script (one player on team 0, no cheat
or debug commands, =synapse_run_id= modoption, =GameType=Synapse Commander 0=)
and an empty per-run =springsettings.cfg=. The app archive depends on stock BAR
and must not shadow BAR files: an archive =modoptions.lua= replaced BAR's and
aborted unit-definition loading. The engine runs in its own process group;
teardown sends SIGTERM to that group only, escalates to SIGKILL after a bound
and records the result. The lock is the rig's atomic =mkdir= lock with a
=pid== owner line, compatible with its shell =vmlock.sh=. Run under the rig's
=with-vmlock.sh=, the launcher inherits that wrapper's hold (its exported
=VMLOCK_OWNER= matches the lock's owner line), records the owner line, and
leaves the release to the wrapper.

Order of a run: manifest (rig/app commits, engine/map hashes, game commit,
start-script, settings, archive and module hashes, scenario, clock mode,
presentation) and =RUN_START= are written before the engine starts. The client
waits for an observation with its unit (the owned unit nearest =W1= minus 400
along x, not the team's start commander) and probes the visible foreign unit
that drifted least while the smoke unit is idle and that unit is still in
sight. It then submits one =TASK advance=, watches later observations for
displacement, submits the remaining negative probes once the unit has stopped,
and checks that neither the smoke unit nor the probed unit moves afterwards. Engine outbox effects and scenario events are ingested into
the same ledger, each effect citing the receipt or event that caused it. The
ledger's =sim_frame= is the frame of ingestion; a record ingested after a later
frame keeps its own frame as =source_frame= or =engine_frame=.

=verdict.json= is computed from the verified ledger and the client's HTTP
transcript. =PASS= needs every check: engine hello; unit and waypoint =W1=
observed; advance accepted; displacement over 50 map units observed within 300
frames of the receipt, at a frame later than the receipt; =order_done= within
600 frames; submission, receipt, effect and moved observation in causal ledger
order; each probe rejected with its stable code (gateway or engine layer) and
no effect or acceptance in the ledger; no movement after the probes; ledger
verified and classified as not autonomous; no other engine run on the host
during the run (a process whose executable is a file named
=spring-headless=, sampled every 0.2 s; its command line is kept in the private
verdict); bounded teardown. The probes are an
unsupported verb, =PRODUCE=, a raw-engine payload, an unknown observation, an
expired intent, an expiry more than 900 frames ahead, a repeat advance of the
unit already at =W1=, a foreign (Gaia) unit, a caller-supplied identity, and a stale
observation over 900 frames old. The HTTP path cannot express a wrong team:
the gateway injects principal and team, which the identity probe checks.

Evidence limits: the client's intents are preloaded, so the ledger classifies
the run as =scripted_replay=; it is not autonomous play. It is headless, not a
visual demo. It moves one unit to a fixed waypoint and is not the Broken Relay
mission. The ledger hash chain detects accidental corruption, not forgery.
The bridge emits no recent receipts or effects inside its observation frames,
so the public =recent_receipts= and =recent_effects= lists are empty; the
authoritative receipts and effects come from the separate outbox stream and are
recorded in the ledger. Accepted gateway residuals: a GET failure other than a
ledger error may drop the connection without a recorded response, the request
timeout bounds each receive rather
than the whole request, and observation entities are passed through as the
bridge filters them rather than field-allowlisted by the gateway.
=tests/test_loop_orchestration.py= exercises the same orchestration with an
in-process fake engine; it checks wiring and verdict rules, not the engine.

* Agent commander run
=python3 -m synapse_commander run-agent= takes the same launch arguments as
=run-smoke= plus =--model= (default =claude-sonnet-5=), =--call-budget= (20),
=--call-timeout= (60 s) and =--deadline= (600 s). Instead of the scripted
client, =agents/commander.py= loops: read the bounded observation over HTTP,
build a prompt from it and its own past decisions and receipts, call the model
out of process, parse exactly one decision (an =IntentEnvelope/v1=, a wait or
done), and submit an intent through the gateway. The engine keeps running
while the model thinks. No negative probes are sent.

The model route is the already-authenticated Claude CLI (=claude -p
--output-format json=, tools disabled, no session persistence, stdin closed,
bounded time); no credential is read or stored. The manifest declares the
pinned model, the call budget and the system-prompt hash. Output that is not
exactly one valid decision for the observation shown is rejected client-side,
counted, and the rule it broke is fed back on the next call; it is never
repaired or replaced by a scripted intent. Each call adds an =INFERENCE=
record citing the observation it saw; the gateway's =INTENT_SUBMITTED= cites
that record and carries the decision label only if the submitted envelope is
the one the model produced. Raw prompts and outputs are kept in the private
=decisions.jsonl=, never in the ledger.

Optional provider routes use the same one-call =ModelReply= seam and only the
documented HTTPS OpenAI-compatible chat endpoint: OpenRouter uses
=OPENROUTER_API_KEY= and =https://openrouter.ai/api/v1=; Crusoe uses
=CRUSOE_API_KEY= and =https://api.inference.crusoecloud.com/v1=. A run chooses
one explicit route and model; the route sends a system prompt and bounded
observation as chat messages, has one bounded non-streaming request, and does
not retry or silently fall back to Claude or a scripted action. A missing key,
HTTP failure, malformed response, or unavailable reported model is a model
error, never an accepted decision. Keys are request headers only: never argv,
prompt, ledger, private decision record, or error body. Provider access and
model availability remain event-day setup dependencies; no live request is
implied by the fake-route tests.

=run-agent --route codex= and =run-rescue --mode agents --route codex= use a
separate Codex CLI adapter (default =gpt-6.1-sol=). It is invoked with an
explicit model and no fallback in a fresh empty directory and temporary
=HOME=; existing CLI authentication is referenced through =CODEX_HOME= and is
never copied or read by the app. An ephemeral =model_instructions_file=
replaces Codex's built-in coding instructions with the game system prompt;
=project_doc_max_bytes=0= prevents project instruction discovery. User
configuration, rules, MCP, web search, and every available
command/browser/app/plugin/image/sleep tool feature are disabled in its argv.
The bounded observation prompt is stdin only; stdout/stderr are capped and the
timeout terminates the CLI process group. The route accepts exactly one final
agent-message JSON event; every tool or execution event is a route error.
Codex 0.163's JSON stream does not carry a per-turn model field, so inference
records mark its explicit =--model= identifier as
=model_provenance: configured_no_fallback= rather than provider-reported.

=run-rescue --mode agents --route openrouter= gives every mind an OpenRouter
route (default model =nvidia/nemotron-3-nano-30b-a3b=, reasoning on,
=max_tokens= 4096 with a 1500-token reasoning budget; Nemotron emits unusable
text with reasoning off, and unbudgeted reasoning used all of 1200 or even 4096
tokens on the commander prompt; a reply cut at the cap is the route error
=max_tokens exhausted=). The run
stops before the engine starts if =OPENROUTER_API_KEY= is unset. Each
inference record carries its route and the provider's reported token counts
and cost; the verdict's =live_inference_recorded= check sums the cost. The
default route stays =claude=.

=PASS= needs: hello; unit and =W1= observed; an accepted advance chosen by the
model; displacement within 300 frames after its receipt; =order_done= within
600 frames; inference, submission, receipt, effect and moved observation in
causal ledger order; no effect from a rejected intent; the call budget kept;
the exclusivity and teardown checks; and the verified ledger classifying the
run =agent_only=, which requires the declared model to have produced the
required =advance_to_W1= decision. Limits: one unit, fixed waypoint, headless,
not visual; agent-only autonomy on this smoke task says nothing about play
quality on a real mission.

* Live rescue variations
Select these with =run-rescue --mode agents --scenario NAME= and the same
engine, gateway, provider and recording arguments as the baseline rescue.
The commander and stranded =M1= each have their own live model, token and view.
Manufactured reasoning bodies receive independent models under their actual
=job-N= principal, within the eight predeclared job slots. Job numbers follow
all production, including fixed-program bodies; a fixed bot built first must
not prevent a reasoning mind built second from acting. An unembodied slot has
no model calls, and a fixed body has no mind view. Production, division of work,
search and recovery remain model choices within the physical rules.

The agents manifest declares those job slots as =optional_principals=. Unused
slots do not count as active minds. The shared =$child= decision binding asks
for a delivered commander delegation and a live action by the same realized
child, regardless of its production number. Physical mission outcome and
this evidence of delegation are reported separately. Model decisions do not
establish physical success without the engine outcome.

In agents mode, =--call-budget= bounds calls per live mind. The manifest records
=model_calls_per_principal= and the aggregate =model_calls= ceiling across all
ten bounded slots (commander, target and eight optional jobs). Unembodied slots
make zero calls. The final check reconciles each mind's attempted-call count
with the inference ledger and checks both limits; route failures consume calls.

=python3 -W error -m unittest tests.test_dynamic_minds= exercises second-job
activation, own-view isolation, unused slots and run checks with test doubles;
native runs are needed to establish gameplay behavior.

| Scenario | Version | Spare bodies | Spare reasoning chips | Spare fixed chips | Extraction deadline |
|----------+---------+--------------+-----------------------+-------------------+---------------------|
| =rescue_baseline= | =6-provisional= | 2 | 1 | 1 | 400 simulated seconds |
| =rescue_last_chip= | =1= | 1 | 1 | 0 | 400 simulated seconds |
| =rescue_short_window= | =1= | 2 | 1 | 1 | 300 simulated seconds |

The Last Chip leaves only one manufacturing opportunity. Spending it on a
body that cannot extend the radio link leaves no replacement deployment.
Closing Window puts the same rescue under a shorter deadline; model latency,
delegation delay and travel all consume that window. A late return is a
timeout even if the mind is still alive. Every variant requires five simulated
seconds inside extraction before success. These are deliberately small
variations on the same surveyed corridor, target and extraction positions.

The gateway exposes only the selected table's bounded public =briefing= and
=scenario.mission= rules, after matching its identity to the engine view.
=timeout_frames= is an absolute simulation-frame limit (30 frames/second);
=frames_remaining= counts down from the observed engine frame, and
=extraction_dwell_frames= is the required dwell. They are available to every
mind and the text play interface. The target's hidden position, current
condition and cause remain outside this projection. The baseline table is
unchanged. These variants add no repair, towing, wildlife or jamming mechanics.

Table/projection tests establish loading, inventory accounting, geometry
preservation and filtering. Only a native live run establishes playability or
its outcome. Retain each run's scenario id/version/hash, model route,
inference and intent records, intervention records and engine outcome; do not
replace a failed live attempt with a scripted success.

* Stranded-mind local policy
=agents/m1_policy.py= provides a scripted target policy for shared use by
rescue rehearsal and interactive drivers. It has no I/O, model calls or access
to scenario truth. =next_action(observation, State())= returns a new immutable
state and at most one proposal with =label=, =type= and =payload=. The caller
wraps that proposal in its M1 session envelope, submits through the gateway,
and calls =record_receipt(state, http, receipt, intent_id)= for an extraction
TASK. Do not pass status-message receipts to that function.

Only M1's own bounded body view can produce an action. The policy sends status
on contact/reconnection, then every ten distinct linked observations. It
understands delivered commander messages =EXTRACT X Z= and =extract at X Z=,
with nonnegative integer coordinates. The engine still validates map bounds,
ground, authority and legality. It requests movement only on its own body and
does not reissue the same message after a completed command. Explicit refusal
permits at most three attempts, spaced by ten fresh observations; uncertain
transport results remain pending. A matching public =order_done= or an
observed own command-queue transition can finish the local command. Only the
engine's mission outcome can establish extraction.

=python3 -B -W error -m unittest tests.test_m1_policy -v= checks the pure policy
with constructed views. This module-level check does not prove that a driver
has wired it in or that an interactive rescue has completed; verify those
claims in a native run with separate principal streams.

* Loop 1 provisioning contract
The provisioned-rescue extension shares one checked-in scenario declaration
between the Recoil gadget and Python gateway:
=game/SynapseCommander.sdd/scenarios/rescue_smoke.json=.  The gadget selects
it only through =synapse_scenario=rescue_smoke= and both consumers require
=ScenarioTable/v1=.  It declares the one factory, versioned chassis and chip
controller identifiers, provisional total body/chip inventory, commander chip,
waypoint and objective. The gateway does not duplicate this allow-list.

When the engine declares this scenario, the bounded public observation may add
=commander=, =budgets=, up to four =factories= with at most eight jobs each, and a typed
=PRODUCE= permission. It keeps only declared factory/chassis/controller IDs
and has the same 32 KiB public cap. Known choices remain visible when their
body or chip count is zero: inventory and queue legality stay authoritative in
the engine, which reports =budget_exhausted= or =chip_unavailable=. Loop 0's
fixed =TASK advance= boundary and W1 observation remain unchanged.

* Loop 1 provisioning run
=python3 -m synapse_commander run-provision= takes the =run-smoke= arguments and
runs a scenario table (default =rescue_smoke=) with the scripted client in
=agents/provision.py=, through the same gateway and recorder. It waits for the
bound commander, budgets and the =PRODUCE= permission; submits one =PRODUCE=
of the first declared chassis with the first controller whose chip count is
positive; waits for the spend in =budgets= and for an owned unit carrying that
controller; submits the same =PRODUCE= again, now unfunded; and advances the
produced unit to =W1=.

=PASS= needs: hello; scenario observed; the =PRODUCE= accepted; bodies and the
chosen chip each down by one; the produced unit observed with its controller;
the second =PRODUCE= rejected =chip_unavailable= or =budget_exhausted=, with no
effect and unchanged budgets; =commander_bound=; =unit_created= carrying the
controller and the job's id, and =factory_job_done= naming the same unit;
=PRODUCE= submission, receipt, =factory_job_started=, =unit_created=,
=factory_job_done=, then the advance's submission, receipt and =order_started=
in ledger order; the advance accepted with displacement within 300 frames and
=order_done= within 600; the ledger verified and not autonomous; exclusivity
and bounded teardown. Limits: scripted fixture, one production, headless unless
=--engine-binary spring=; scenario values are provisional.

* Initial rescue-world run
=python3 -m synapse_commander run-world= (default =--scenario rescue_baseline=)
sends no intents. It reads the world through the gateway until it has at least
three observations spanning 90 frames, then checks them against the
evaluator-only =world_init= scenario record the engine writes to the ledger at
start: every predeployed asset appears in the roster by name, only assets in
contact carry a unit id; observed budgets equal the evaluator's available
counts, and total = deployed + lost + available for bodies and each chip;
exactly one distress report on the declared asset, observed before the start
(negative =observed_frame=), whose age equals frame minus that and grows;
=world_init= precedes the first observation. No player observation, neither
an HTTP response nor a ledger =OBSERVATION= record, may carry evaluator-only
keys (seed, cause, state, contact, assets, inventory), the hidden cause, a
hidden unit's id, or a hidden asset's true position as an entity or report.
The seed check and the usual ledger, exclusivity and teardown checks also
apply. Limits: initial world only (no target behaviour or sensing), headless,
scripted fixture; table values provisional.

* Bonded commander control interface
=agents/bonded.py= provides =BondedCommander= and =BondedClaudeRoute= for
human-guided model play. The controller reads only the commander's gateway
observation, gives the model the latest text order, and sends its validated
typed action through the existing client. The caller supplies an inference
ledger and an =on_order(text, generation)= callback that records human guidance
before accepting it. Raw orders and model output belong only in private
evidence; human guidance and model-selected actions retain separate sources.

=control.ControlServer(controller, token, host='127.0.0.1', port=8090)= serves
a small browser page, authenticated =GET /status=, and authenticated JSON
=POST /orders= with a =text= field or =POST /pause= with an empty object.
Laptop dictation can enter text directly; a local transcription client can use
the same order endpoint with bearer authentication. The caller owns token
creation, a private connection to the loopback listener, and server teardown.
The browser holds its token in memory. It receives no raw gateway credentials.

The controller limits model calls and elapsed time. Replacing or pausing an
order discards any in-flight decision from the previous order. Pause prevents
new decisions; game orders already submitted may finish. No action is sent
without a recorded inference. The current verification is
=python3 -B -W error -m unittest tests.test_bonded_control -v=: controller tests
use a model test double, and HTTP tests use a real loopback listener. Launcher
integration, a remote laptop connection, and live model-to-engine effects
still require separate verification; these module tests do not establish a
playable rescue run.
